# Contributor guide (people and coding agents)

This is a public Rust/egui LDAP application. Read README.md, CONTRIBUTING.md and SECURITY.md. Use the pinned toolchain and Cargo.lock; run `make fmt` and `make check` before a pull request. CI uses GitHub-hosted runners with read-only permissions; never add secrets, private endpoints, privileged pull-request workflows or publishing without maintainer approval.

Keep verified LDAPS and hostname checks mandatory. Preserve explicit OS-keychain opt-in with no plaintext fallback, endpoint-scoped credentials, shared credential_attribute redaction, preview and confirmation before writes, paged virtualized navigation, cancellation and cache limits. Certificate parsing is display-only and performs no network fetching. Use synthetic entries and generated certificates only; never include real credentials, LDIF, personal data or screenshots from real directories. No telemetry.

Everything written here is public and permanent: code, commit messages, pull-request text, comments, logs and screenshots. Do not include internal host names, IP addresses, home-directory or machine paths, account names, employer or lab details, ticket links from private systems or credentials. Use `example.org` names and documentation address ranges in tests and docs. Commit with a GitHub noreply identity. `python3 tools/public_guard.py` checks the tree and your commits.

Workflow: work on a branch, open a pull request against `main`, wait for the required checks, and let a code owner review. Do not merge your own pull request, push to `main`, create or move tags, create releases or packages, or change repository settings; those are maintainer actions and are enforced by repository rules. Only the maintainer edits `.github/workflows/**`. Keep changes small and test the platform you claim. Public build identity is separate from any private-build configuration. See docs/validation.md for what CI can prove.
