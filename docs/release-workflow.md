# Public alpha release workflow — preparation only

The .github/workflows/release.yml definition is JSON-form YAML (valid YAML; structural tests use the standard library). It is dormant on Forgejo and must be carried into the reviewed sanitized public tree. Do not run it locally or push it to GitHub as an agent. Johann reviews/pushes the public snapshot himself, waits for native CI, then separately approves a tag/release. Creating this file performs no GitHub operation.

Only push of a v* tag triggers it; there is no workflow_dispatch, PR, workflow_run or pull_request_target path. The helper accepts only 0.1.0 alpha tags, verifies the tag already identifies the checked-out public commit and that it is on origin/main. No automatic tag creation/movement. Windows x64 uses native MSVC with the C runtime statically linked, macOS-15 is native arm64, Linux uses Ubuntu 24.04 x64. No Intel, installers, self-hosted runners, internal registry or signing identity.

Build jobs have contents:read, persisted checkout credentials disabled, pinned actions/tools, two-way matrix concurrency, and full native public checks. Compile-time stamping uses the tag version, public commit and build-start UTC. Each immutable run artifact has the archive, a target-specific checksum and BUILD sidecar; every archive includes matching BUILD.json, LICENSE/NOTICE, README/release notes and third-party licence metadata/texts. No dependency cache is shared with a privileged job.

The separate fresh publish runner needs all builds successful, checks out the same reviewed commit without persisted credentials, downloads artifacts from this run only, never installs dependencies/builds/runs binaries, and validates the exact three platform sets/hashes/embedded identity. Only this job has contents:write. Only its draft step receives GitHub's ephemeral automatic token, via GH_TOKEN; **no stored repository/organization secrets** are used. That token is necessarily the authority to create a GitHub draft, not a signing identity. Unspecified permissions are none; no actions:write, id-token, packages or attestations permission.

The helper invokes gh with --verify-tag --draft --prerelease --latest=false, refuses an existing release rather than overwrite, and verifies draft/pre-release flags afterward. There is no public-publish/edit path. A failed upload may leave an incomplete draft; Johann must inspect/clean it manually before an explicitly approved rerun. Artifact checksums and BUILD metadata are integrity/provenance records, not publisher signatures or proof of reproducibility. Before manually publishing, Johann downloads and checks every asset and follows docs/release-candidate.md. No changes to repository settings/protection are made by this preparation.

Pin provenance: checkout v5.1.0; upload-artifact v4.6.2; download-artifact v4.3.0, all full commit SHAs. Reviewed against the official action refs and GitHub workflow/release documentation. Runner OS labels are fixed supported versions, not immutable VM digests; BUILD records compiler/target and exact public source. Linux tarballs target that glibc baseline; compatibility with older distros is not claimed.

Official references: [workflow permissions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions), [release draft/prerelease API semantics](https://docs.github.com/en/rest/releases/releases#create-a-release), [hosted runner architecture](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). Signing/notarization is deliberately absent from this CI workflow; from alpha.4 Johann may Developer-ID sign and notarize the macOS zip locally and replace it in the draft, following [signing.md](releases/signing.md) (the workflow itself stays tag-only and draft-only, and Windows stays unsigned). Never advise disabling OS protections.
