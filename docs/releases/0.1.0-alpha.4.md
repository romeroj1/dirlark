# DIRLARK 0.1.0-alpha.4 — draft release notes

Early-adopter **pre-release**. No stable support guarantee; use a test directory and inspect every write preview. Preview/readback conflict checks are best effort, not atomic transactions. Directory permissions remain the server's responsibility.

**Update recommended:** the alpha.3 source (prepared but never published as a download) contained `rustls-webpki` 0.103.15, which has a published certificate-verification advisory. This release fixes it (see Security); public `main` keeps the old version until alpha.4. Build from source or use an official alpha.4 or later download.

Planned downloads: Windows x64 ZIP (MSVC), macOS arm64 app ZIP, Linux x86_64 tar.gz. No Intel Mac, Windows ARM, installers, DMG, AppImage or universal Mac package. Source is Apache-2.0 with NOTICE and dependency licence texts. Every archive includes BUILD.json with the exact public source commit, compiler, target, version and build date. SHA256SUMS verifies download integrity; it is not a trusted-publisher signature or reproducible-build proof.

## What changed since alpha.3

- **Security:** the TLS stack's `rustls-webpki` is updated from 0.103.15 to 0.103.16 (RUSTSEC-2026-0382). Affected versions could accept certificate chains through emSign intermediate certificates that are now distrusted (their private keys are public), when the operating-system trust store or a selected CA bundle still trusts the emSign root. DIRLARK verifies LDAPS server certificates against the system roots plus an optional CA bundle, so a build with the old library whose store trusts that root could be exposed to a spoofed server. No alpha.3 download was ever published. Hostname and trust checks themselves are unchanged and remain mandatory.
- **Credentials:** a password (typed, remembered or saved) with a **blank Bind DN** no longer connects. It used to bind anonymously, ignore the password and look like a successful login. DIRLARK now refuses with "Bind DN is blank: this would connect anonymously and ignore the password. Enter a Bind DN or clear the password." Anonymous connect with no password works as before. Tests prove that no password is sent on an anonymous bind and that passwords with symbols and non-ASCII text reach the server byte for byte.
- **Attribute display:** harmless password-policy operational attributes (`pwdChangedTime`, `pwdPolicySubentry`, `pwdAccountLockedTime`, `pwdFailureTime`, `pwdReset`) are now shown. `userPassword`, `pwdHistory` and every other credential-like attribute stay hidden, in the inspector, previews and default exports.
- **App icon and UI icons:** DIRLARK has an application icon (macOS bundle, Windows executable, Linux icon set and desktop file, window/dock icon). The interface uses a small open-licensed icon set (Phosphor Icons, MIT, licence included in the archive): tree icons by object class (domain, OU, person, group, device, other), tab and toolbar icons, a compact Copy icon with tooltip and accessible label, and lock/shield/warning state icons.
- **macOS signing:** the release process now supports Developer ID signing and notarization of the macOS app on the maintainer's own Mac. See "Signing status" above for what is true of your download.
- **Polish:** Rows per page shows its 25–500 range; a search with zero rows explains that quick search matches literal text (an asterisk is not a wildcard) and points to the LDAP filter box; a plain `ldap://` endpoint is refused with an explicit message; switching saved profiles scrolls the connection form back to the top so Profile name and Bind DN are visible.

## Known limits

- Windows and Linux are unsigned; a macOS download is signed only where the signing status above says so. Gatekeeper/SmartScreen can warn or block; managed policies may prohibit running it. Never disable platform protections. See the README for permitted per-app handling and verification.
- The new Windows executable icon is built from a precompiled resource file; it has been checked with a linker but not yet on a finished Windows release build.
- Windows no-GPU VM anonymous verified-LDAPS and certificate-viewer use have been confirmed on an earlier internal build. Real-GPU/high-DPI, Windows Credential Manager, ACLs and the final release archives need separate runtime checks.
- Apple Silicon runtime is confirmed on earlier builds; Intel Mac is untested and excluded. Local temporary Keychain roundtrips passed; broader user/managed-Mac flows, and keychain use under the Developer ID signature, remain untested until checked on the signed build.
- Linux headless rendering and isolated GNOME Secret Service roundtrip pass CI; full desktop unlock/prompt/Wayland workflows remain untested. Native hosted compilation/tests do not establish interactive hardware coverage.
- **Password persistence is experimental on untested platforms/flows.** Leave Save password unchecked for session-only use. No plaintext fallback exists. Owned password buffers are zeroized best effort; library/OS buffers may retain copies.
- Live authenticated directory writes/ACL interactions remain untested. Generated in-process LDAPS peers cover bind/search/write/schema/error paths. Use a disposable authorized directory before real editing.
- Screen-reader integration is deferred (icon-only buttons carry accessible names, but this has not been tested with a screen reader). TLS verification cannot be disabled. Certificate decoding is display-only: signature, chain, revocation and hostname are not validated; no validation URLs are fetched.
- Cache eviction is deliberate. Export covers cached results, not a whole directory. Server size/time/admin limits can truncate results; refine searches rather than assuming totals.

No telemetry, automatic updates or crash uploads. Report bugs with synthetic data. Report vulnerabilities privately through SECURITY.md, never through public credential/LDIF attachments.
