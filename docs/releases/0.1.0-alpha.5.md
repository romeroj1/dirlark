# DIRLARK 0.1.0-alpha.5 — release notes

Early-adopter **pre-release**. No stable support guarantee; use a test directory and inspect every write preview. Preview/readback conflict checks are best effort, not atomic transactions. Directory permissions remain the server administrator's responsibility.

Downloads: Windows x64 ZIP (MSVC), macOS arm64 app ZIP, and Linux x86_64 tar.gz. There is no Intel Mac, Windows ARM, installer, DMG, AppImage or universal Mac package. Archives include build identity, SHA256SUMS, license notices and dependency license material. Hashes detect changed downloads; they are not a publisher signature or proof of reproducible builds.

## What changed since alpha.4

- Added a display-only TLS security panel for a connection. It shows captured negotiated-protocol and peer-certificate evidence, including names, validity and fingerprints, and can save the supplied certificate chain as PEM. TLS verification remains mandatory. Certificate display does not add trust, signature, revocation or hostname validation, and does not fetch AIA/CRL/OCSP URLs.
- Added `dirlark --keychain-selftest`, a headless create/read/delete probe for the native credential store. It reports pass/fail without printing credential values.
- Updated Tokio from 1.53.3 to 1.54.1.

## Known limits

- The TLS panel displays evidence; rustls performs the connection's trust, hostname and signature checks. A failed verification remains a failed connection.
- Interactive platform and hardware coverage, credential-store flows on untested systems, and the final release archives need their own checks. See the [validation scope](../validation.md).
- Password persistence is experimental on untested platforms and flows. Leave it unchecked for session-only use. No plaintext fallback exists.
- Preview/readback conflict checks are best effort, and live authenticated directory writes and ACL interactions remain untested. Use a disposable authorized directory before editing real data.

No telemetry, automatic updates or crash uploads. Report bugs with synthetic data only; report vulnerabilities privately through [SECURITY.md](../../SECURITY.md).
