# DIRLARK 0.1.0-alpha.6 — release notes

Early-adopter **pre-release**. No stable support guarantee; use a test directory and inspect every write preview. Preview/readback conflict checks are best effort, not atomic transactions. Directory permissions remain the server administrator's responsibility.

Downloads: Windows x64 ZIP (MSVC), macOS arm64 app ZIP, and Linux x86_64 tar.gz. There is no Intel Mac, Windows ARM, installer, DMG, AppImage or universal Mac package. Each archive includes `BUILD.json`, license notices and dependency license material. The release also carries `SHA256SUMS` and per-target `BUILD-<target>.json` files. Hashes detect changed downloads; they are not a publisher signature or proof of reproducible builds.

On macOS, extract the ZIP with Finder, Archive Utility or `ditto -x -k <archive.zip> <destination>`. Plain `unzip` may add AppleDouble `._` files that make `codesign --strict` fail.

## What changed since alpha.5

- **Replica TLS hostname bypass (Issue #18)**: Added optional `tls_skip_hostname_verification` checkbox in connection profiles to allow connecting to directory replicas or IP endpoints presenting cluster certificates. Verification remains strictly enforced against the provided CA bundle: trust anchor chains, cryptographic signatures, and certificate validity windows cannot be bypassed, and hostname bypass requires an explicit non-empty CA bundle path to prevent rogue public-CA MITM attacks.
- **In-app background updater foundation (Issue #19)**: Integrated an in-app background update engine with a bottom-right status pill displaying update readiness, asset staging, and restart prompts. Update downloads are restricted to HTTPS and verified GitHub release asset endpoints, with double SHA256 checksum verification before extraction and relaunch. Staging into application support enables seamless in-place updates without reapplying macOS Gatekeeper quarantine.
- **Vulnerability remediation & dependency updates**: Upgraded `url` to 2.5.9 resolving `RUSTSEC-2026-0592`, alongside open Dependabot dependency bumps across the crate tree.

## Known limits

- Hostname bypass is permitted only in conjunction with a custom CA bundle. System root trust stores cannot be used with hostname bypass disabled.
- Interactive platform and hardware coverage, credential-store flows on untested systems, and the final release archives need their own checks. See the [validation scope](../validation.md).
- Password persistence is experimental on untested platforms and flows. Leave it unchecked for session-only use. No plaintext fallback exists.
- Preview/readback conflict checks are best effort, and live authenticated directory writes and ACL interactions remain untested. Use a disposable authorized directory before editing real data.

No telemetry, tracking, or crash uploads. Report bugs with synthetic data only; report vulnerabilities privately through [SECURITY.md](../../SECURITY.md).
