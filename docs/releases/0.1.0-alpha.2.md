# DIRLARK 0.1.0-alpha.2 — draft release notes

Early-adopter **unsigned pre-release**. No stable support guarantee; use a test directory and inspect every write preview. Preview/readback conflict checks are best effort, not atomic transactions. Directory permissions remain the server's responsibility.

Planned downloads: Windows x64 ZIP (MSVC), macOS arm64 app ZIP, Linux x86_64 tar.gz. No Intel Mac, Windows ARM, installers, AppImage or universal Mac package. Source is Apache-2.0 with NOTICE and dependency licence texts. Every archive includes BUILD.json with the exact public source commit, compiler, target, version and build date. SHA256SUMS verifies download integrity; it is not a trusted-publisher signature or reproducible-build proof.

## What changed since alpha.1

alpha.1 was never published. Its macOS app bundle had no valid seal, so a downloaded copy was reported as "damaged" instead of the usual unidentified-developer prompt. alpha.2 applies an ad-hoc seal to the bundle and re-verifies it after zipping and extracting, so the release job fails rather than ship a broken bundle. The seal is not a publisher identity: the app is still **not Developer-ID signed or notarized**, and macOS will still ask you to approve it once with System Settings → Privacy & Security → Open Anyway (when your policy permits). Windows and Linux archives are unchanged.

## Known limits

- No Apple Developer ID/notarization or Windows Authenticode signature. Gatekeeper/SmartScreen can warn or block; managed policies may prohibit running it. Never disable platform protections. See the README for permitted per-app handling and verification.
- Windows no-GPU VM anonymous verified-LDAPS and certificate-viewer use have been confirmed on an earlier internal build. Real-GPU/high-DPI, Windows Credential Manager, ACLs and the final release archives need separate runtime checks.
- Apple Silicon runtime is confirmed on an earlier internal build; Intel Mac is untested and excluded. Local temporary Keychain roundtrip passed; broader user/managed-Mac flows remain untested.
- Linux headless rendering and isolated GNOME Secret Service roundtrip pass CI; full desktop unlock/prompt/Wayland workflows remain untested. Native hosted compilation/tests do not establish interactive hardware coverage.
- **Password persistence is experimental on untested platforms/flows.** Leave Save password unchecked for session-only use. No plaintext fallback exists. Owned password buffers are zeroized best effort; library/OS buffers may retain copies.
- Live authenticated directory writes/ACL interactions remain untested. Generated in-process LDAPS peers cover bind/search/write/schema/error paths. Use a disposable authorized directory before real editing.
- Screen-reader integration is deferred. TLS verification cannot be disabled. Certificate decoding is display-only: signature, chain, revocation and hostname are not validated; no validation URLs are fetched.
- Cache eviction is deliberate. Export covers cached results, not a whole directory. Server size/time/admin limits can truncate results; refine searches rather than assuming totals.

No telemetry, automatic updates or crash uploads. Report bugs with synthetic data. Report vulnerabilities privately through SECURITY.md, never through public credential/LDIF attachments.
